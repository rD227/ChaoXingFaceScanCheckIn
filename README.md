# ChaoXingFaceScanCheckIn

超星学习通人脸与二维码签到工具的开源项目。

当前处于架构设计阶段，尚未发布可运行的签到应用。接口可用性、登录流程和不同活动的校验要求需要在实际开发中逐项验证。

## 是否需要服务器

不一定。第一版已选择 **Android App、本机处理、不购买服务器**：让用户手机负责网络请求和会话管理。

| 方案 | 自建后端 | 适用场景 |
| --- | --- | --- |
| Android App：网页界面 + 原生网络层 | 不需要 | 安卓手机自用，账号和本地资料保存在本机 |
| GitHub Pages 静态网页 / PWA | 无法托管后端 | 扫码、图片压缩、界面演示；完整业务依赖接口是否允许浏览器跨域访问 |
| 网页 + 自建 API | 通常需要 | 浏览器或微信直接打开、兼顾多个手机平台 |
| 静态网页 + 云函数 | 仍有后端 | 请求量小、只在操作时处理请求，不需要长期运行的任务 |

这里的“不需要服务器”指不需要运营本项目自己的服务器；仍然需要联网访问超星服务。

## 第一版的实现顺序

1. 先验证登录、Cookie 保持、官方活动读取和真实结果查询。
2. 实现相机扫码与相册识别，并检查二维码对应的活动。
3. 实现用户本人人脸资料的本机管理，区分“资料已保存”“验证已通过”和“签到已成功”。
4. 在 Android 中接入原生网络层、本机存储与登录状态清理。
5. 使用实际账号和课程验证接口，确认结果后再发布可用版本。

手机端可使用 H5 界面配合原生 HTTP、相机与安全存储。仅把网页包进 WebView，而没有原生网络适配，并不能解决全部跨域与 Cookie 问题。

GitHub Pages 可以用于项目文档、静态界面和下载入口，不能在其中运行 Node.js、Python 或 Go API。二维码解析与照片压缩可以在前端完成；官方人脸校验和签到记录仍由超星服务器决定。

## 云端配置

如果选择完整网页版本，小范围使用可先以 **2 核 CPU、2GB 内存、20–40GB 磁盘** 的轻量应用服务器作为起步估算，再通过压测调整。此估算适用于轻量 API 和会话处理，不包括大量用户持续轮询或自建人脸模型推理。

初期不需要 GPU、Kubernetes、独立 Redis 或独立数据库集群。可先在本机开发，待接口验证和客户端方向确定后再购买服务器。云函数也可以处理短请求，但仍属于后端，需要验证会话、上传、出站访问与执行时限。
