# 许可证选择与代码来源

## 当前状态

仓库最初只有 GPL-3.0 许可证，没有业务代码。本次添加的是独立编写的架构文档，未引入前面讨论的第三方项目代码。

第一版选择保留原有 GPL-3.0 LICENSE。后续包元数据和发行说明应与实际使用的代码许可证保持一致。

## GPL/AGPL 能不能用

可以。GPL 和 AGPL 允许修改、再分发和商业使用，同时规定了相应的源码、声明和许可条件。AGPL 还对修改后程序通过网络提供服务的情况规定了源码提供要求。

README 中额外表达的反对二开、商业化等意愿，与标准许可证的许可内容可能不一致。选择上游代码时，应核实权利来源与授权条件，不自行假定冲突已经解决。

## MIT 怎么选

- 我们独立编写、且有权授权的代码，可以选择 MIT。
- 使用第三方 MIT 代码时，保留其版权与许可证声明。
- 使用其他许可证的依赖时，分别满足相应要求，不能把它们的许可证全部替换成 MIT。
- 复制或改写第三方 GPL/AGPL 代码后，不能仅通过改文件名、换语言或替换 LICENSE 就将这些代码作为 MIT 发布。
- 若需要重新授权第三方代码，应取得相应权利人的有效授权。

MIT 允许后续使用者将其纳入闭源软件；如果希望衍生发行版继续提供源码，GPL 可能更符合目标。这是项目对下游使用方式的选择，不由 App 或网页的形态决定。

## 代码来源记录

后续引入依赖、代码片段、图片、图标或模型时，记录来源、版本、许可证和必要声明。只有公开可读的网页脚本，不能据此认定其已被开源授权。

独立开发时可以记录协议行为与接口观察，但应避免直接移植没有相容授权的源码实现。
